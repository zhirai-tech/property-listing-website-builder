## 四、浏览器验证发现并修复的真实缺陷

这一节是本次交付最重要的部分：**以下问题全部由真实浏览器操作发现，纯自动化测试均未捕获**。

1. **地图功能从未真正可用（第 4 阶段判定原为「否」）**
   展示页依赖 `window.L`，但全仓库**没有任何加载地图库的 `<script src>`**，因此必然走降级分支 —— 功能等于没做。
   **修复**：引入 `leaflet@1.9.4`（BSD-2-Clause）并由应用以 `/vendor/leaflet/` 同源提供（不依赖任何 CDN，`script-src` 保持 `'self' 'nonce-…'` 严格策略）；公开展示页的 `style-src` 按需放宽为 `'unsafe-inline'`（Leaflet 必须用 `style` 属性定位瓦片，且 nonce 与 `unsafe-inline` 不能并存），后台接口不放宽；新增瓦片失败检测，全部瓦片失败时如实降级为地址文本；清理了容器内残留的占位文本。
   **实测**：Leaflet 1.9.4 加载成功，**10/10 瓦片加载成功**，渲染出房源真实坐标的 OpenStreetMap 街区地图（证据：`docs/evidence/15-public-page-map-working.png`）。

2. **严格的 CSP 阻断了内联样式，后台界面样式大面积失效**
   最初的 CSP（nonce + 无 `unsafe-inline`）会拦截所有 `style="…"` 属性，控制台报出 8 条 CSP 违规。
   **修复**：把 24 处内联样式全部改为 CSS 类，使 `script-src` 与后台 `style-src` 都保持严格。

3. **后台「退出登录」按钮不可见**
   深色侧栏内的 `.btn.ghost` 使用了深色文字 + 透明背景，形成深色叠深色。
   **修复**：为侧栏按钮单独指定浅色文字与边框。

4. **面积单位被写死为「㎡」**
   平方英尺房源（里斯本 1450 sq ft）在列表中显示为「1450 ㎡」—— 直接违反方案「不写死某一国家规则」的原则。
   **修复**：按 `area_unit` 映射显示，实测显示为「1450 sq ft」。

5. **多语言只翻译了房源正文，界面仍是中文**
   英文页面里 `房源介绍` / `价格与费用` / `联系方式` 等区块标题保持中文，不满足「支持多语言界面」。
   **修复**：新增界面词条目录（zh-CN / zh-TW / en / ja，未知语言回退英文），展示页全部界面文案随之切换；房型字典值也一并本地化（`apartment` → `Apartment` / 「公寓」）。

6. **表单错误提示被浏览器原生校验抢占**
   必填项使用 HTML5 `required`，浏览器气泡先于平台校验出现，中文字段级提示永远不会显示。
   **修复**：表单改为 `novalidate`，由平台统一给出中文字段级提示（实测：标题下方显示「标题不能为空」，并在表单底部汇总）。

7. **提醒「计划时间」按浏览器时区渲染却标注为 Asia/Shanghai**
   当地 09:00 被显示成 03:00，且标注时区为 Asia/Shanghai，直接误导用户。
   **修复**：新增 `fmtDateTimeInZone()`，提醒一律按自身时区渲染并显式标注时区；同时新增「跳到该提醒时间」入口，避免整日推进落到发送时段之外而看起来像规则失效。

8. **提醒投递结果被立即覆盖**
   投递后立刻重渲染，用户看不到投递报告。
   **修复**：先重渲染再把结果写回新容器，并列出每条提醒的投递明细。

9. **移动端「附加费用」标签被挤成竖排**
   **修复**：窄屏下 `dt/dd` 改为上下堆叠（实测手机版截图 `12-public-page-mobile.png`）。

10. **列表页面积单位、导出死链、备份/媒体绕过存储适配器等**
    详见 `phase-3` 与 `phase-8` 报告的修订记录。其中**备份与 `/media/*` 绕过存储适配器**属于隐患级问题：一旦改用对象存储，备份会静默丢失全部素材、展示页图片会全部 404。

## 六、上线前必须关闭的缺口

按方案第 8 阶段要求，以下为**必须**在上线前处理，未处理前不得商用发布：

1. **TLS 终结**：应用不做 TLS 终结、无 HSTS，必须由 Nginx / Caddy 等反向代理提供 HTTPS。
2. **生产配置**：设置强 `ADMIN_PASSWORD` 与随机会话密钥（≥32 字符），`PUBLIC_BASE_URL` 改为 https 真实域名（`NODE_ENV=production` 时已强制校验这三项）。
3. **SMTP 投递实测**：`MAIL_PROVIDER=console` 只写日志；必须配置真实 SMTP 并**实测一封提醒邮件**。
4. **周边信息服务**：确认 `MAP_OVERPASS_ENDPOINT` 在目标网络可达，或改为自建实例；明确免费额度与超额费用。
5. **瓦片服务合规**：阅读并遵守 OpenStreetMap 瓦片使用政策；高流量场景应改用商业瓦片服务或自建。
6. **许可证复核**：`docs/licenses.md` 是 2026-10-12 的快照，商用前必须重新核验（含 `typescript` 为 Apache-2.0、`qrcode-generator` 包内无 LICENSE 文件这两处证据偏弱项）。
7. **备份策略**：备份未加密且只存本机，需加密并同步异地，且**至少完成一次真实恢复演练**。
8. **真实域名验证**：自定义域名需在真实公网 DNS 上完成 TXT 所有权验证。

## 七、明确未验证 / 未完成的内容

以下内容**不得**按已完成报告：

1. PropertyWebBuilder 的**实际部署验证未做**（本机无 Ruby 工具链）—— 第 0 阶段的已登记偏差。
2. **周边信息未用真实数据验证** —— 端点可配置，但本机环境对该公共实例的请求一律返回 HTTP 406（4 种请求形式均为 406，判断为网络策略拦截），只验证了降级路径。
3. **自定义域名验证未在真实公网 DNS 上跑通** —— 全流程已用可注入 DNS 适配器覆盖测试，但无自有域名做端到端实测。
4. **SMTP 适配器未对真实邮件服务器投递过**。
5. **未做依赖漏洞审计**（`pnpm audit`）与**性能压测**；仅消除了列表接口的 N+1 查询。
6. 12 种可选语言中仅 4 种有完整界面词条；后台界面仅中文；自由文本字段（详细地址、附加费用）无翻译通道。

1. 在具备 Ruby 环境与自有域名的机器上补做第 0 阶段的 PropertyWebBuilder 部署对照，以及第 6 阶段的真实 DNS 域名验证。
