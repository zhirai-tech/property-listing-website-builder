# 修复报告：`adminEnabled` 服务端权限控制

**修复日期**：2026-10-13
**基准 HEAD**：`435cd6d3e4ab57af383ccb60ce04687134076dca`（未变）
**修复范围**：只实现 `adminEnabled` 的服务端权限执行。**未开发插件安装 / 更新 / 卸载等生命周期功能。**

---

## 一、根因

`adminEnabled` 是一个**可查询、永不生效**的权限位：

| 位置 | 情况 |
| --- | --- |
| `config.ts:33,68,83,96` | 定义：`TierLimits.adminEnabled`（free=false、basic/pro=true）——「该套餐是否包含插件在线管理后台」 |
| `config.ts:117,124` | 列入 `OVERRIDABLE_FIELDS`，管理员可调整 |
| `quota.ts:154-157` | **实现了判定规则**：`if (!limits.adminEnabled) return deny('admin_not_included', …)` |
| `quota.ts:233` | 在额度摘要里返回给前端展示 |
| **调用方** | **全库搜索：除了测试，没有任何路由调用过 `action: 'plugin.admin'`** |

也就是说：规则写好了，但**没有任何接口受它保护**。前端即便隐藏了按钮，
直接请求 API 也不会被拒 —— 因为根本没有需要请求的接口，也没有守卫。

---

## 二、先查清的事实：这个权限位是什么，不是什么

在动手前核实了三件事，它们决定了修复该怎么做：

### 2.1 它是**套餐能力位**，不是「系统管理员身份」

`DEFAULT_TIER_LIMITS` 里 `adminEnabled` 与 `hostingEnabled` 并列，都是套餐能力。
**平台侧不存在「管理员身份」这个概念** —— `users.role` 里只有房东端工作区属主的 `owner`，
平台会话的 payload 里 `role` 恒为 `'user'` 且**校验时会真的检查它**（`auth.ts:316`）。

**因此我没有、也不应该发明一个平台管理员身份。** 没有把所有会员设为管理员，
也没有授予任何默认权限。

### 2.2 房东端后台是**另一套系统**，不能与它互相授权

`/api/admin/*` 由**单一共享口令**的 `admin_session` 保护（`app.ts`），
与平台会话完全独立。让 `adminEnabled` 去授权房东端后台会是**严重的安全倒退**
（等于把「买了会员」当成「拿到了运营后台钥匙」），也正好是任务要求 5 警告的「把会员套餐与管理权限混为一谈」。**本次明确不做。**

### 2.3 插件**生命周期**接口不存在，且本次不予开发

安装 / 启用 / 禁用 / 升级 / 卸载 / 依赖管理**全都没有实现**
（`plugin_installations` 表零读写代码 —— 属另一个已记录问题）。
所以「保护所有插件管理接口」在当前代码里**没有对象**。

### 2.4 有两个接口**刻意不能**加锁

| 接口 | 为什么不能锁 |
| --- | --- |
| `GET /api/platform/plugins` | **插件目录**，所有用户建项目都要用。锁上会直接破坏普通用户（违反要求 8） |
| `GET /api/platform/safety-stats` | 代码里有**明确的设计注释**：「不是运营专属。**免费用户也能看到「我的请求为什么老是被拒」**」。锁上会推翻这个刻意决定 |

## 三、修复内容

### 3.1 统一的服务端权限检查入口

`src/http/routes/platform.ts` 新增 `requirePluginAdmin(request, reply)`：

```ts
const requirePluginAdmin = (request, reply) => {
  const user = requireUser(request, reply);          // 未登录 → 401
  if (!user) return null;
  const decision = checkQuota(ctx.db, {              // ← 复用既有规则，不另写一套
    userId: user.id,
    tier: user.tier,                                 // 已过会员到期解析
    action: 'plugin.admin',
    membership: user.membership,
  }, ctx.adapters.clock.now());
  if (!decision.allowed) {
    reply.code(403).send(new DomainError('FORBIDDEN', decision.message).toResponse());
    return null;
  }
  return user;
};
```

**所有受保护路由一律走它** —— 规则只有一份，不会出现「某个接口漏判」。

**到期会员天然被覆盖**：`user.tier` 已经过 `currentPlatformUser` 的到期解析，
所以到期会员在这里拿不到管理能力，**不需要在这里再判一次到期**（也不会因此改变到期规则）。

### 3.2 受保护的接口

| 接口 | 说明 |
| --- | --- |
| **`GET /api/platform/plugins/:id/admin`** | **新增**：插件管理视图（只读） |

返回：插件的契约与配置细节（版本 / `apiVersion` / `pageType` / `structuralKeys` /
`capabilities` / 字段清单 / 可执行性）、**当前用户自己的**项目与发布计数、
以及**当前套餐对该插件的可用性**（`adminEnabled` / `hostingEnabled` / 项目上限）。

**它是只读的**，不涉及安装、启停、升级、卸载 —— 符合「本次只修复权限控制」的边界。

新增它的理由：权限位必须有**真实的受保护对象**才能被端到端验证。
`checkQuota` 那条规则已经存在，但没有任何路由用它；
只写守卫不挂路由，等于换了个地方继续「永不生效」。

**它不返回**：其他用户的数据（计数只统计自己）、任何密钥、任何内部错误。

### 3.3 涉及文件

| 文件 | 改动 |
| --- | --- |
| `src/http/routes/platform.ts` | 新增 `requirePluginAdmin` 守卫；新增受保护的 `GET /api/platform/plugins/:id/admin` |
| `tests/platform/admin-enabled.test.ts` | **新增** 7 个场景测试（A–G） |

会员到期规则、任何数据库结构。

## 五、场景 A–G 真实 HTTP 测试结果

全部在隔离临时环境、通过真实 API 执行。

| 场景 | 预期 | 实际结果 |
| --- | --- | --- |
| **A** 未登录 | 拒绝 | ✅ 受保护接口 **401**；**百分号编码路径 `/%61pi/...` 同样 401**；响应不含管理视图内容 |
| **B** 普通用户 | 拒绝 | ✅ **403**，`code=FORBIDDEN`，提示说明缺少管理能力；**不泄露管理视图内容** |
| **C** 已到期会员 | 不因会员身份获得管理权限 | ✅ **403**，提示含「**到期**」与「**续期**」；**把到期时间改成未来后同一用户立刻 200** —— 证明差别就在有效期，而不是「会员一律禁」 |
| **D** 有权限的会员 | 正常使用 | ✅ `basic` 与 `pro` 均 **200**，含结构键/字段/能力/套餐可用性；不存在的插件 **404**（不变成插件探测器） |
| **E** 篡改参数 | 一律无效 | ✅ 3 种查询参数、4 种伪造请求头、请求体伪造、伪造签名 Cookie —— **全部被拒**；库中套餐未被改写 |
| **F** 普通用户不受影响 | 正常 | ✅ 建项目 201 / 预览 200 / 下载 200 / 插件目录 200 / 安全统计 200；会员发布后**匿名访问公开页 200**；**不能发布他人项目** |
| **G** 无遗漏绕过入口 | 逐一核对 | ✅ 2 个受保护接口 × 3 种身份全部符合预期；5 个刻意开放的接口对免费用户 200、未登录 401；**3 个房东端后台接口对平台会员一律 401**；管理视图**不统计他人项目**（=0）；不含任何密钥字符串 |

### 关键证明

临时让守卫放行（模拟修复前「`adminEnabled` 从不生效」）后重跑：
**场景 B / C / E / G 全部失败**，报错分别是
「免费用户应为 403，**实际 200**」「到期会员应为 403，**实际 200**」。
恢复守卫后 **7/7 通过**。
