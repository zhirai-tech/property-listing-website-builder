**当前平台尚未达到「可开放真实用户」的条件；但已达到「可在隔离环境测试」与「可供内部试用」的条件。**

## 三、免费用户流程核对结果

### 3.1 实际跑通的链路（隔离环境实测）

```
注册                      HTTP 201
额度接口                   token=500000  projects=1  revisions=1  generations=3  hosting=false
创建第 1 个项目             HTTP 201
创建第 2 个项目             HTTP 403  「当前套餐最多创建 1 个项目，已达上限。升级套餐或删除已有项目后可继续。」
上传照片                   HTTP 201
在线预览                   HTTP 200（含严格 CSP）
下载                       HTTP 200（ZIP 26472 字节，含 index.html + assets/）
发布到托管                 HTTP 403  「当前套餐不包含平台在线托管。可下载网页文件自行部署，或升级套餐。」
```

### 3.2 额度初始值与配置方式

`src/platform/config.ts:60-75` 是**唯一**的默认值来源：

```
free:  maxProjects 1 · maxAiGenerations 3 · maxAiRevisions 1 · tokenQuota 500_000
       hostingEnabled false · adminEnabled false · projectRetentionDays 7 · quotaPeriod 'none'
```

- **无散落硬编码**：全库搜索 `500000|500_000` 仅命中 `config.ts:66`；前端 `public/app/app.js` 只渲染接口返回值，无任何额度字面量。
- **可配置**：`platform_settings` 表 + `writeStoredSetting()`，`OVERRIDABLE_FIELDS` 白名单；测试 `foundation.test.ts:341`「管理员可在运行时调整额度」。
- **注意**：产品描述提到「1 个页面项目、1 次 AI 修改、500,000 Token」，代码里另有 `maxAiGenerations: 3`。**这不矛盾**（生成次数是独立维度），但**产品文档未明确写「生成 3 次」**，属文档与实现的表述差异。

### 3.3 绕过尝试（全部失败）

| 尝试 | 结果 |
| --- | --- |
| 创建第 2 个项目时在请求体塞 `userId`/`user_id`/`tier` | 403 |
| 用不存在的项目 ID 调 `generate` | 404 |
| 用他人项目 ID 做 8 种操作 | 全部 404 |
| 请求体提交 `tokens: 999999` | 额度不变（0 → 0） |

### 4.1 真实后端权限（有证据）

| 项 | 证据 |
| --- | --- |
| tier 来自数据库而非请求体 | `projects.ts:337` `SELECT tier FROM users WHERE id=?`；实测伪造 `tier:'pro'` 无效 |

| 额度耗尽拒绝 | 测试 `foundation.test.ts:299`、`:341` |

### 4.2 仅存在结构、无实际执行逻辑

| 项 | 说明 |
| --- | --- |
| **`plugin.admin` 额度动作** | `quota.ts:99,140` 定义并实现判定，但**全库无任何调用点** → 会员的 `adminEnabled` 权限**没有任何受它保护的接口** |

**`/media/*` 不鉴权**（既有设计）：实测匿名可读取任何已知 storageKey 的图片（`HTTP 200 image/png`）。这是**自洽的**（公开展示页必须能加载照片），且 storageKey 含随机短码、**无法枚举**。但**不区分草稿与已发布** —— 未发布项目的照片若 key 泄漏同样可取。

- 上传路径穿越专项测试
- 导入/导出/备份的目录越界访问
- 并发与故障注入

- **规则**：草稿修改是否会直接破坏已经发布的页面。
- **状态**：**FAIL**
- **证据**：`src/http/routes/public-sites.ts:77-85` —— 当 `project.pluginId === 'listing'` 时，公开页渲染 `aggregateFor(scoped, propertyId)`（**当前房源记录**），**不使用** `published_version_id` 指向的发布快照。而 `saveDraft` 会通过 `specSyncerFor('listing')` 把 spec 同步进 `properties`。
- **实测**：发布后页面含「核对房源项目」；改草稿后再次请求**同一公开地址**，内容变为「草稿新内容」（`含旧=false 含新=true`）。
- **影响**：**平台主力插件不产生不可变发布快照**。用户改草稿 = 线上立即变更，无法「改完再确认后上线」。`custom-page` 插件**没有**这个问题（已验证渲染发布快照）。
- **证据边界**：本次只验证了 title 同步；未验证照片、价格等全部字段。
- **依赖**：不依赖 Mock，纯本地行为。
- **建议方向**：listing 公开路由改为渲染发布版本快照（或明确产品语义：房源类不提供快照，并在界面说明）。

### 问题 2 ·【高】导出 HTML 含格式错误的 URL（缺斜杠）

- **规则**：下载的页面能否独立运行。
- **状态**：**FAIL**
- **证据**：`src/services/export-service.ts:113` —— `html.replaceAll('/media/', 'assets/')`。当输入是**绝对 URL** `http://host:port/media/...` 时，替换结果为 `http://host:portassets/...`（**协议+端口后直接跟 `assets`，缺 `/`**）。
- **实测**（隔离环境导出真实 ZIP）：`http://127.0.0.1:3733assets/prp_28a3638a-…/mv6s3pej-….png`
- **影响**：**该 URL 在任何环境下都无法解析**。若它出现在 `og:image` 等元数据中，分享预览图必然失效。
- **纠正**：我在更早的报告里曾判定这处替换「**经验上不可达**」—— **该判断错误**。本轮在平台房源插件的真实导出中复现了它。
- **建议方向**：替换前先把绝对 URL 归一化为相对路径，或在替换时补上斜杠。

### 问题 3 ·【中】空内容项目可「发布成功」，但地址打不开

- **规则**：发布状态、版本号与实际公开页面内容是否一致。
- **状态**：**FAIL**
- **证据**：`src/platform/projects.ts:328-357` —— `publishProject` 只检查所有权与托管额度，**不调用 `checkSpec` 校验内容**。
- **实测**：从未写入任何内容的项目（`spec = {}`）→ 发布 `HTTP 200`、`status=published`、返回 `publicUrl`；请求该地址 → **404**。
- **影响**：用户会以为发布成功并把打不开的链接分享出去。
- **建议方向**：发布前校验内容非空（可复用 `checkSpec`），失败返回 422 并说明原因。

### 问题 4 ·【中】AI 产出为空时返回 403 FORBIDDEN

- **规则**：错误语义正确性（间接影响额度提示与监控）。
- **状态**：**FAIL**
- **证据**：`src/http/routes/platform.ts:484-485` —— `const status = result.code === 'not_found' ? 404 : result.code === 'duplicate_task' ? 409 : 403;` 然后统一 `new DomainError('FORBIDDEN', …)`。
- **实测**：`generate` 返回 **HTTP 403 / code=FORBIDDEN**，message 却是「这次没有生成出页面内容。可以再点一次…」。
- **影响**：403 语义是「无权访问」，而实际是「AI 没产出内容」。前端若按 403 显示「升级套餐」会误导；监控/WAF 会把成批 403 当作攻击特征；且提示文案（「再点一次」）与状态码自相矛盾。
- **建议方向**：内容/供应商类失败改用 422 或 502，并定义独立错误码。

### 问题 5 ·【中】版本只能查询，不能回滚

- **规则**：是否能够识别和恢复历史版本。
- **状态**：**MISSING**（回滚部分）
- **证据**：`GET /api/platform/projects/:id` 返回 `versions`（含 kind/versionNo）；全库搜索 `versions/.*restore|restoreVersion|revertTo` **零命中**；实测请求版本回滚路由 → 404。
- **建议方向**：新增「回滚到某版本」接口（把该版本 spec 写回草稿或直接重新发布）。

### 问题 6 ·【中】插件生命周期管理缺失

- **规则**：插件是否有统一的启用、禁用、版本和依赖管理机制。
- **状态**：**MISSING**
- **证据**：`plugin_installations` 表在 `src/db/migrations.ts:303-313` 定义（含唯一索引），但 **`src/`、`tests/`、`public/`、`scripts/` 全库无任何读写**。
- **影响**：无安装记录、无启停、无依赖解析、无升级路径。当前只有「内置清单硬编码」一种形态。
- **建议方向**：明确产品定位 —— 若「只支持内置插件」，应删表或标注为保留结构并写入文档。

### 问题 7 ·【中】会员 `adminEnabled` 权限无实际执行接口

- **规则**：会员专属管理功能是否由后端执行。
- **状态**：**MISSING**（该权限的执行面）
- **证据**：`quota.ts:99` 定义 `'plugin.admin'` 动作、`:140` 实现判定；**全库无调用点**。
- **影响**：`adminEnabled` 是「可查询但永不生效」的权限位，前后端都无接口受它保护。
- **建议方向**：要么实现对应接口，要么从 `TierLimits` 移除以免误导。

### 问题 8 ·【中】托管到期处理未实现

- **规则**：会员托管额度和到期时间是否由后端执行；到期后是否按规则限制托管。
- **状态**：**MISSING**（到期部分）
- **证据**：`projects` 表有 `published_at`/`unpublished_at`，**无 `hosting_expires_at`**；无到期扫描任务。
- **已实现的部分**：手动「停止托管」可用，且**不销毁内容与版本**（实测版本 4 条保留）。
- **建议方向**：产品需先确定「托管是否到期」；若需要，加列 + 定时任务（可参考既有 `scripts/expire-projects.ts`）。

### 问题 9 ·【低】`member_until` 到期不会自动降级

- **证据**：迁移 v3 增加 `users.member_until`，全库**无到期判定代码**。
- **影响**：会员到期后权限不变，需人工改库。
- **建议方向**：在 `limitsFor(tier)` 前统一做一次「到期则按 free 处理」的判定。

### 问题 10 ·【低】项目不存在时返回 404 但错误码是 FORBIDDEN

- **证据**：实测 `POST /api/platform/projects/{不存在}/generate` → `HTTP 404`，body `{"error":{"code":"FORBIDDEN","message":"项目不存在"}}`。
- **影响**：客户端按 `code` 分支会误判为权限问题。
- **建议方向**：`not_found` 分支使用 `NOT_FOUND` 码。

### 问题 11 ·【低】`/media/*` 不鉴权且不区分草稿/已发布

- **状态**：**PARTIAL**
- **证据**：匿名 `GET /media/<storageKey>` → HTTP 200。
- **说明**：这是**既有设计且自洽**（公开页需加载照片），storageKey 含随机短码**无法枚举**。但未发布项目的照片若 key 泄漏同样可取。
- **建议方向**：可接受；若要收紧，按 `properties.status` 过滤。

### 问题 12 ·【低】导出页含平台回链，非完全独立

- **证据**：导出 HTML 含 `http://127.0.0.1:3733/p/导出核对`（「分享链接：…」）与 ZIP 内 `share-url.txt`；另含品牌外链 `https://zhirai.cloud`。
- **影响**：自部署后该「分享链接」仍指向原平台。属产品语义问题，非故障。
- **建议方向**：明确该链接的预期；或改为提示用户自行填写。

- 「AI 生成」全部返回 `no_page_output`（mock 从 prompt 抽取 `键: 值`，`custom-page` 需要 `html` 而 mock 产不出）→ **所有 AI 相关实测都是「失败路径」**。

## 十一、试用结论

四个阶段**严格区分**：

| 阶段 | 是否可进入 | 依据 |
| --- | --- | --- |
| **可在隔离环境测试** | ✅ **可以** | `pnpm verify`（45/45）与 6 个自建探针全部在临时环境跑通；不触碰真实数据 |
| **可供内部试用** | ✅ **可以**（有保留） | 免费闭环、额度强制、隔离、既有房源功能均有实测证据。**保留条件**：内部试用者须知悉问题 1（房源类改草稿即上线）与问题 2（导出 URL 错误） |
| **可开放真实用户** | ❌ **不建议** | ① **核心 AI 能力零真实验证**——用户会拿到一个「生成不出页面」的产品；② 问题 3（发布成功但地址打不开）会直接损害信任；③ 无到期/回滚/插件生命周期 |
| **可正式公开部署** | ❌ **不可以** | 无公网验证、无支付、无运维配套（备份调度、监控、域名签发均未验证） |

**给内部试用者的最少前置动作建议**：

1. 配置真实 AI Provider（`AI_PROVIDER`/`AI_BASE_URL`/`AI_API_KEY`/`AI_MODEL`）并**至少真实生成一次成功页面** —— 这是目前唯一完全空白的环节。
2. 知悉并接受问题 1、2、3 的现状（或先修）。
3. 仅使用 `custom-page` 插件做对外演示，避开问题 1。
