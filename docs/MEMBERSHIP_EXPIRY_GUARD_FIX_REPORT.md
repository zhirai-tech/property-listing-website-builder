## 一、根因

`users.member_until` 这个字段（迁移 v3 加入）**从加进 schema 起就只被存储和读取，
从来没有参与过任何判断**：

| 位置 | 情况 |
| --- | --- |
| `migrations.ts:232` | `ALTER TABLE users ADD COLUMN member_until TEXT` —— 只是加列 |
| `auth.ts:116,128` | 映射进 `PlatformUser.memberUntil` —— 只是带出来 |
| **写入方** | **全库搜索：没有任何代码写过它** |
| **判定方** | **全库搜索：没有任何地方读过它做判断** |

也就是说：**「会员到期」这件事在服务端根本不存在**。到期后用户照样能发布到平台托管、
照样按会员额度建项目。

**并且没有统一的权限服务**：`users.tier` 被 **6 处**直接读库
（`projects.ts` 4 处、`retention.ts` 1 处、另有会话路径），每处各自判定。

## 二、会员有效期的实际判断规则

新增 `src/platform/membership.ts`，提供**唯一**的判定入口。

### 2.1 字段含义（依据现有代码与数据得出，未做猜测）

- **类型**：`TEXT`，可空。
- **格式**：ISO-8601 瞬间（与项目其它时间字段一致）——
  因此比较的是**时间点**，不存在本地时区与 UTC 混用的问题。
- **写入方**：没有任何代码写过它，现有会员的值一律为 `NULL`。

### 2.2 三种状态如何区分

现有数据**无法区分「永久有效」与「未设置到期时间」**，因此按以下规则处理：

| `tier` | `member_until` | 生效套餐 | 说明 |
| --- | --- | --- | --- |
| `free` | 任意 | `free` | 免费用户不受会员有效期影响 |
| 非 free | `NULL` | **原套餐** | **视为不限期** |
| 非 free | 可解析且 `now <` 它 | 原套餐 | 未到期 |
| 非 free | 可解析且 `now >=` 它 | **`free`** | **已到期** |
| 非 free | 无法解析 | **`free`** | **视为已到期**（fail-safe） |

**为什么 `NULL` 视为不限期**：现有代码里没有任何地方写入该字段，
也就是说**当前所有会员的 `member_until` 都是 NULL**。若把 NULL 当作「已到期」，
这次改动会让**全部现有会员立刻失去权限** —— 那是用一个猜测去推翻既有行为。
反过来当作不限期，与改动前的实际效果一致，是兼容的选择。

**为什么无法解析时按已到期处理**：读不懂的到期时间不应该换来付费权限。
这是唯一一处刻意 fail-closed 的地方，在此明确说明。

### 2.3 边界规则

有效期是 **[起, 止) 半开区间**：`now < member_until` 有效，`now == member_until` **已到期**。
到期时刻本身不再授予权限，避免「刚好卡在到期瞬间」出现两种解释。
（毫秒级断言见单元测试。）

### 3.1 为什么在会话入口做统一判定

`currentPlatformUser()` 是**每一个已认证平台请求的唯一入口**（`requireUser` 走它）。
在把 user 交给路由之前先降级，所有下游（额度判定、托管发布、AI 任务、界面展示）
自动按免费套餐处理 —— **不需要每个接口各写一遍到期判断**（那样迟早会漏）。

对于**不经会话**的判定点（发布、AI 任务、恢复、回收扫描），统一走 `membershipForUser()`，
只有一个版本，不会出现第二个实现。

### 3.2 顺带修正的一处真实不一致

`publishProject` 等服务的默认时间参数原本是 `new Date()`，而会话路径用的是
`ctx.adapters.clock.now()`。应用启用 `devTimeTravel` 时 clock 是可控的 FakeClock ——
**两条路径会对「现在」有不同理解**，可能出现「会话说已到期、发布流程说没到期」。
已把这 5 处默认值改为应用时钟。

**生产环境没有 FakeClock，clock 就是系统时钟，与 `new Date()` 等价，行为不变。**

### 3.3 提示文案

到期时 `checkQuota` 的拒绝信息会带上：

> **会员已于 2026-01-02 03:04:05 UTC 到期。续期后可继续使用。**当前套餐不包含平台在线托管…

—— 说「续期」而不是笼统的「升级套餐」。用户明明买过会员，却被告知「升级」，
会以为系统把他的会员弄丢了。

## 四、哪些 API 受到保护，哪些不受影响

### 受会员有效期保护（到期即拒绝）

| 能力 | 执行点 | 到期后 |
| --- | --- | --- |
| 发布到平台托管 | `publishProject` → `checkQuota('hosting.publish')` | **403** |
| 会员额度（项目数、生成次数、Token） | `createProject` / `runAiTask` / `restoreProject` | 按 **free** 额度 |
| 项目保存期限 | `expireOverdueProjects` | 按 **free** 的 7 天 |
| 插件在线管理后台（`adminEnabled`） | — | 该权限位**目前无任何接口受它保护**（属另一个已记录问题，本次未动） |

### **不受**影响（免费功能，到期后照常）

建项目（free 额度内）、保存草稿、预览、**下载/导出**、删除、回收站恢复、
查看额度、示例画廊、插件清单。

**已发布页面不会被自动下线** —— 到期只影响「能否再发布」，不影响已经发布出去的内容。
