## 二、缺陷一：5 处错误映射各自实现，AI 失败被报成「没有权限」

### 根因

平台路由里有 **5 处**各写了一套三元表达式，规则还不一样：

```ts
// 只有「发布」那条被补过 422：
const status = result.code === 'not_found' ? 404 : result.code === 'not_publishable' ? 422 : 403;
// 其余四条把**任何**失败都报成 403 FORBIDDEN：
const status = result.code === 'not_found' ? 404 : result.code === 'duplicate_task' ? 409 : 403;
return reply.code(status).send(new DomainError('FORBIDDEN', result.message).toResponse());
```

后果：

| 实际情况 | 修复前 | 应该 |
| --- | --- | --- |
| AI 没产出内容（换个描述就能过） | **403 FORBIDDEN** | 422 |
| 上游 AI 服务不可用（等会重试可能就好） | **403 FORBIDDEN** | 502 |
| 项目不存在 | 状态 404，**响应体 `code` 却是 FORBIDDEN** | 404 + NOT_FOUND |
| 未知插件（参数写错） | 403 FORBIDDEN | 400 |

**影响**：客户端按 `code` 分支会显示「升级套餐」；监控会把它们统计成越权尝试。

### 修复

新增**唯一**映射表 `httpErrorFor(code)`，5 处全部改用它。
分类依据是「谁的错、能不能重试」：

| 类别 | 状态 | 错误码 |
| --- | --- | --- |
| 对象不存在 / 指错了对象 | 404 | `NOT_FOUND` |
| 状态冲突（未归档时恢复、未托管时停止、重复任务） | 409 | `CONFLICT` |
| 调用方参数错（未知插件 / 用户） | 400 | `VALIDATION_FAILED` |
| **内容或产出不符合要求** | **422** | `UNPROCESSABLE` |
| **上游 AI 服务不可用** | **502** | `DEPENDENCY_UNAVAILABLE` |
| 服务端自身故障 | 500 | `INTERNAL`（本次新增的错误码） |
| 其余（额度、套餐、所有权） | 403 | `FORBIDDEN` |

**刻意没动的一处**：`property_not_owned`（引用别人工作区的房源）保持 **403 + 「不属于你」**。
我一度想改成 404（不泄露资源是否存在），但那会改变一个与本轮缺陷无关的既有行为，
且有测试专门断言 403。**已回退**。

## 三、缺陷二：一条错误提示会清空整个编辑器

**这是在真实浏览器里才发现的**，纯后端测试永远看不到。

发布被拒后，编辑器**整个消失了** —— 字段、按钮、AI 区全部不见，只剩一条错误文字。

### 根因

```js
function showError(container, error) {
  clear(container);        // ← 清空整个容器
  ...
}
```

而 `renderEditor()` 里 `const box = $('editor')`，发布失败调用的正是 `showError(box, error)`。
于是**编辑器本身被清空**，换成一条错误信息。

**影响**：用户看得到「为什么失败」，却**没法改、没法重试**，只能退回列表重新打开项目。

### 修复

`showError` 改为**只移除上一次由它插入的提示**（`.alert.error` 与 `.hint.error-issues`），
其余内容原样保留；并让提示 `scrollIntoView`，避免长编辑器里错误落在可视区之外。
